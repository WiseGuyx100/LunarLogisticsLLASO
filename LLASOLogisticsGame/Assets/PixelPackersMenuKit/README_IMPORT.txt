PIXEL PACKERS - PORTABLE MENU UI KIT

IMPORT INTO THE OTHER PERSON'S UNITY PROJECT
1. Extract this ZIP.
2. Open their project in Unity 6 (recommended: 6000.6.2f1 or newer Unity 6).
3. In Unity choose Assets > Import Package > Custom Package.
4. Select PixelPackers_MenuOnly.unitypackage and click Import with all items selected.
5. Open Assets/PixelPackersMenuKit/Scenes/PixelPackersMenu_Demo.unity.
6. Press Play. The UI is created at runtime; an empty Scene/Game preview before Play is normal.

CONNECT IT TO THEIR GAME
1. Stop Play. Select the 'Pixel Packers Menu Kit' object in the Hierarchy.
2. In Portable Menu Controller, enter the EXACT name of their gameplay scene in Game Scene.
3. Optionally set Tutorial Scene, Timed Scene, Lunar Scene and Multiplayer Scene.
   Timed falls back to Game Scene if blank. Blank/unlisted destinations show an unavailable page.
4. Add the menu scene AND their gameplay scenes to File > Build Profiles > Scene List.
   Put the menu first if it should open when the game starts.
5. Press Play: Single Player > PC now loads their scene.

WHAT'S INCLUDED
- Standalone menu demo scene; UI is generated by its attached controller at runtime.
- Original transparent team logo and lunar menu backdrop.
- Rounded panels, white button hover/selection, animated page changes.
- Controller icons and selection page; settings with correctly bounded sliders.
- Working scene-loading hooks, volume setting, and Quit button (works in a built game).
- C# source with its own PixelPackersMenuKit namespace and new asset GUIDs.

THIS IS A UI KIT, NOT THE GAMEPLAY SYSTEM
Warehouse, terrain, cargo, scanner, VR rig, QR server and local multiplayer gameplay are excluded.
PC/Gamepad/Phone/VR selections store a choice and invoke a callback. They do NOT install controls,
start Quest Link, generate a QR code or create split-screen players in the recipient's game.
Their game must implement those systems, or remove/hide the unwanted buttons in the script.
No game packages or ProjectSettings are overwritten. No background music or sound assets included.

INTEGRATION HOOKS
PortableMenuController.SelectedControl: PC, Gamepad, Phone or VR.
PortableMenuController.SelectedMode: Practice, Tutorial, Timed, Lunar or LocalMultiplayer.
Read these static properties from a script in the destination scene.
Inspector events: On Control Selected (string), On Mode Selected (string),
On Sensitivity Changed (float). Connect these to their own persistent managers as needed.
Look sensitivity is a saved UI value; their camera must read/apply it or listen to the event.
PlayerPrefs keys: PP.MenuKit.Volume and PP.MenuKit.Sensitivity.

DEPENDENCIES / TROUBLESHOOTING
Requires Unity UI (com.unity.ugui). Most Unity 6 projects already include it.
If UnityEngine.UI is missing, install Unity UI through Window > Package Manager > Unity Registry.
Uses the Input System if ENABLE_INPUT_SYSTEM is enabled; otherwise uses the built-in input module.
If using legacy input, set Active Input Handling to Input Manager (Old) or Both as appropriate.
No OpenXR, URP, TextMesh Pro, third-party or paid packages are required by this kit.
The UI uses built-in UI materials, so it can be used in Built-in, URP or HDRP projects.
The demo script generates a camera only if the scene has no enabled MainCamera.
This is runtime-generated UI: edit labels/layout in PortableMenuController.cs.
Import into a backup/copy first if their project already has a customized main menu.
